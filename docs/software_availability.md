# Software Availability Plan

This document is the publication-facing availability checklist for IsoComp.

## Current Repository Assets

- Python package metadata: `pyproject.toml`
- Command-line entry point: `isocomp`
- Unit tests: `tests/`
- Continuous integration: `.github/workflows/ci.yml`
- Small BED12/GTF/BAM fixtures generated by `tests/conftest.py`
- End-to-end CLI and report checks: `tests/test_cli.py`

## Archived Software and Supporting Data

| Resource | Archived version | DOI |
| --- | --- | --- |
| IsoComp software | v0.1.0 | [10.5281/zenodo.21206056](https://doi.org/10.5281/zenodo.21206056) |
| Supporting data: Stereo-seq alignments and mouse transcript completeness simulations | v0.1.0 | [10.5281/zenodo.24548169](https://doi.org/10.5281/zenodo.24548169) |

The software DOI identifies a fixed archive of the v0.1.0 release. The GitHub
`main` branch is the development source and may contain later changes. For
analyses based on a GitHub checkout, report the exact commit used and archive
that revision when a persistent record of those changes is required.

`CITATION.cff` provides the citation for the archived software release. Cite the
supporting-data DOI separately when reusing those data.

## Reviewer Smoke Test

From a clean checkout:

```bash
python -m pip install -e ".[test]"
pytest
isocomp --version
isocomp --help
```

Expected behavior:

- `pytest` passes without external sequencing data.
- CLI tests generate small BED12/GTF/BAM fixtures in temporary directories and
  verify TSV, JSON, PNG/PDF plots, and HTML/PDF reports.
- The installed command reports its version and displays command-line help.

## Release Checklist

The v0.1.0 archive listed above is already available. For subsequent releases,
complete these items before manuscript submission:

1. Confirm the version in `pyproject.toml` and `isocomp/__init__.py`.
2. Run `pytest` on Python 3.10, 3.11, and 3.12 or confirm GitHub Actions passed.
3. Confirm `isocomp --version` and `isocomp --help` work after installation.
4. Build a source and wheel distribution:

   ```bash
   python -m pip install build
   python -m build
   ```

5. Create a new signed or annotated Git tag matching the release version.

6. Create a GitHub release from that tag and attach:

   - source archive
   - wheel or source distribution from `dist/`

7. Archive the GitHub release or release archive on Zenodo, Figshare, or Software
   Heritage and record its persistent identifier. Update `CITATION.cff`, the README,
   and this document to identify the new archived version.
8. Confirm the manuscript's software version or commit, archive identifier,
   supporting-data citation, contact information, and funding details.
